# ТЗ: RuNet Checker — MVP

Черновая спецификация. Конкретный список ресурсов и технический способ проверки (HTTP, TCP, DNS и т. д.) уточняются во время разработки. Ниже зафиксированы продуктовые правила, без которых нельзя ни реализовать, ни проверить классификатор.

Текущая сборка приложения: **0.1.2** (`versionCode` 3). Правила нумерации — в [versioning.md](versioning.md).

## Цель

Android-приложение автоматически определяет текущее состояние интернет-соединения и, в частности, переход мобильной сети в режим ограниченного доступа по «белому списку».

## 1. Состояния сети

Приложение определяет четыре состояния:

| Статус | Описание |
| --- | --- |
| ONLINE | Доступен полноценный интернет |
| WHITELIST | Доступны разрешённые российские ресурсы, но глобальный интернет недоступен |
| OFFLINE | Интернет фактически отсутствует |
| UNKNOWN | Проверку не удалось корректно завершить, состояние определить нельзя |

VPN сам по себе не определяет состояние интернета и является дополнительной информацией.

## 2. Проверяемые ресурсы

Ресурсы делятся на две группы. В каждой группе — минимум три хоста.

### Global

Стартовый набор для проверки гипотезы:

- `google.com`
- `cloudflare.com`
- `wikipedia.org`

Нужны стабильные глобальные ресурсы из разных сетей. Сайты с собственной, часто независимой блокировкой (`youtube.com`, `instagram.com`) в Global для первой версии не ставим: они зашумят классификатор.

### Whitelist

- `max.ru`
- `yandex.ru`
- `vk.ru`
- при необходимости дополнительные ресурсы

Список можно расширять. Для классификации достаточно одного успешного ответа в нужной группе: несколько хостов нужны как страховка, чтобы падение одного сайта не дало ложный `OFFLINE` или ложный `WHITELIST`.

## 3. Алгоритм определения состояния

Упрощённо:

```
хотя бы 1 GLOBAL доступен
        → ONLINE

все GLOBAL недоступны, хотя бы 1 WHITELIST доступен
        → WHITELIST

все GLOBAL недоступны, все WHITELIST недоступны
        → OFFLINE
```

Несколько ресурсов в группе — страховка, а не требование большинства. Недоступность одного Google не означает `WHITELIST`, если любой другой Global ещё отвечает. Симметрично: если глобальные все молчат, но жив хотя бы один ресурс из белого списка, это `WHITELIST`, а не `OFFLINE`.

### Пороги v0.1

| Global | Whitelist | Состояние |
| --- | --- | --- |
| ≥ 1 | любой | ONLINE |
| 0 | ≥ 1 | WHITELIST |
| 0 | 0 | OFFLINE |

Следствия:

- 1/3 Global + 0/3 Whitelist → `ONLINE` (глобальный интернет есть, даже если российские сайты не ответили);
- 0/3 Global + 1/3 Whitelist → `WHITELIST` (это уже не «нет интернета»);
- 0/3 Global + 0/3 Whitelist → `OFFLINE`.

`UNKNOWN` оставляем для случаев, когда проверку не удалось корректно завершить (сбой checker, нет результатов зондов), а не для частичных ответов.

### Критерий «ресурс доступен»

Для режима белых списков DNS часто ещё резолвится, а HTTPS уже нет. Поэтому DNS-only и голый HTTP без TLS для классификации не используем: операторский редирект легко даст ложный `ONLINE`.

Рабочее определение для v0.1:

- HTTPS до конкретного хоста (TCP + TLS);
- таймаут порядка 3–5 секунд на зонд;
- успех — соединение установлено (HTTP 2xx / 3xx / 4xx; 5xx тоже скорее «хост достижим»);
- провал — таймаут, `UnknownHost`, connection refused, reset, нет маршрута.

Точный транспорт можно уточнить в разработке, но проверка должна подтверждать достижимость хоста, а не только резолв имени.

`ConnectivityManager` («сеть есть») сам по себе белый список не ловит: интерфейс при этом обычно `connected`.

## 4. Мониторинг

Приложение должно самостоятельно отслеживать изменения сети.

Концептуально:

```
Изменение сети
      ↓
Запуск проверки
      ↓
Определение NetworkState
      ↓
Сравнение с предыдущим состоянием
      ↓
Состояние изменилось?
      ↓
Обновить UI + при необходимости уведомить
```

Также должна существовать периодическая контрольная проверка.

Интервалы и конкретный механизм фоновой работы определяются позднее. В v0.1 мониторинга нет: только ручной запуск.

## 5. VPN

Приложение определяет наличие активного VPN как отдельный индикатор. VPN не входит в `NetworkState`.

С версии **0.1.2** по кнопке CHECK параллельно с зондами:

1. Есть ли активный VPN (`TRANSPORT_VPN`).
2. Если VPN есть — HTTPS geo-IP выходного адреса (`https://ifconfig.co/json`, поле `country_iso`). Если VPN нет — geo-запрос не делается.
3. Ошибка geo не валит CHECK: страна тогда «неизвестна», без предупреждения.

UI под статусом сети, до списков хостов:

- VPN выкл;
- VPN вкл, страна `RU` — имя страны на языке приложения;
- VPN вкл, не `RU` — страна и предупреждение: российские сервисы могут не работать, смените сервер или настройте маршрутизацию по приложениям;
- VPN вкл, гео не удалось — «страна неизвестна», без предупреждения.

«Российский» = ISO `RU` только. Блок показывается после первой проверки.

## 6. Интерфейс MVP

Главный экран максимально простой:

```
┌──────────────────────────────┐
│        RuNet Checker         │
│                              │
│           ONLINE             │
│                              │
│ Global Internet     3 / 3    │
│ Whitelist           3 / 3    │
│                              │
│ VPN                  OFF     │
│                              │
│       [ CHECK NOW ]          │
└──────────────────────────────┘
```

Пользователь должен видеть:

- текущий статус;
- результаты Global;
- результаты Whitelist;
- состояние VPN;
- возможность вручную запустить проверку.

Для экрана v0.1 достаточно статуса, счётчиков `Global x/y` и `Whitelist x/y` и кнопки проверки. С 0.1.2 под статусом показывается VPN (вкл/выкл и страна выходного IP после CHECK).

## 7. Уведомления

При существенном изменении состояния приложение отправляет Android-уведомление.

Примеры:

- ограничение интернета: обнаружен режим белого списка, глобальные ресурсы недоступны;
- интернет восстановлен: полный доступ снова доступен.

Не нужно отправлять уведомление после каждой проверки, если состояние осталось прежним.

В v0.1 уведомлений нет.

## 8. Первый этап разработки — v0.1

Не пытаемся сразу реализовать всё.

```
Android App
     ↓
кнопка CHECK
     ↓
NetworkChecker
     ↓
┌─────────────┬─────────────┐
│   GLOBAL    │  WHITELIST  │
└─────────────┴─────────────┘
     ↓
NetworkState
     ↓
ONLINE / WHITELIST / OFFLINE / UNKNOWN
     ↓
отображение результата
```

Без фонового сервиса, уведомлений и сложного UI.

### Цель v0.1

На устройстве, по одной ручной проверке, отличить полноценный интернет от режима белого списка и от полного отсутствия сети.

Успех:

- стабильный `ONLINE` на обычной сети;
- корректная классификация по таблице порогов;
- полевой `WHITELIST` подтверждаем, когда режим реально случится.

### Как доказать, что классификатор работает

`NetworkChecker` лучше сделать чистой функцией:

```
List<ProbeResult> → NetworkState
```

Тогда таблицу кейсов можно прогнать без сети:

| Global | Whitelist | Ожидание |
| --- | --- | --- |
| 3 / 3 | 3 / 3 | ONLINE |
| 1 / 3 | 3 / 3 | ONLINE |
| 1 / 3 | 0 / 3 | ONLINE |
| 0 / 3 | 3 / 3 | WHITELIST |
| 0 / 3 | 1 / 3 | WHITELIST |
| 0 / 3 | 0 / 3 | OFFLINE |

Полевые прогоны на обычном Wi‑Fi, LTE и режиме полёта — второй слой проверки.

### Что сознательно не входит в v0.1

- фоновый мониторинг и интервалы;
- уведомления;
- captive portal;
- раздельный учёт IPv4/IPv6;
- экономия батареи.

VPN-индикатор (вкл/выкл и страна выходного IP) добавлен в **0.1.2**. После рабочего `NetworkChecker` дальше: автоматический мониторинг → уведомления → нормальный UI.
