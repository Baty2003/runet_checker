# Версионирование

Источник правды для номера сборки — [`app/build.gradle.kts`](../app/build.gradle.kts): `versionName` и `versionCode`.

## Поля Android

| Поле | Для кого | Правило |
| --- | --- | --- |
| `versionName` | человек | SemVer на экране, сейчас `0.2.0` |
| `versionCode` | система | целое число, только растёт: 1, 2, 3… |

`versionCode` нельзя уменьшать: установка на устройстве считает больший код более новой сборкой.

## Имя версии

Пока продукт не опубликован как MVP: `0.MINOR.PATCH`.

- **0** — ещё не публичный MVP
- **MINOR** — заметная возможность из ТЗ
- **PATCH** — правка классификатора, хостов, баг

| versionName | versionCode | Состав |
| --- | --- | --- |
| `0.1.0` | 1 | ручная проверка, классификатор |
| `0.1.1` | 2 | логи, тема, языки |
| `0.1.2` | 3 | VPN-индикатор и страна |
| `0.2.0` | 4 | автопроверка, foreground-сервис, уведомления |
| `1.0.0` | 5+ | полный MVP |

Патчи между срезами: `0.1.1`, `0.1.2` — только `versionCode + 1`.

## Git

Каждый новый коммит — это новый git-тег. Промежуточных коммитов без тега нет.

В том же коммите поднимают `versionName` / `versionCode` и ставят тег с тем же именем, что `versionName`:

```bash
git tag v0.1.1
git push origin HEAD
git push origin v0.1.1
```

Обычный коммит с правкой — патч (`0.1.0` → `0.1.1`) и `versionCode + 1`. Заметный срез из таблицы выше — сразу MINOR или `1.0.0`.
